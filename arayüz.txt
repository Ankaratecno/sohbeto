A) HIZ / STABİLİTE
Sorun dilde değil, mimaride. Şu an: vanilla HTML + CSS + JS, tek dosyada
iframe içinde. Bu aslında en hızlı temeldir; yavaşlığın gerçek sebepleri:
  1. Duvar kağıtları JPG olarak geç yükleniyor → WebP/AVIF'e çevir,
     boyutları küçült, service worker'da precache et, CSS'te
     background-image yerine önceden yüklenmiş <img>/decode() kullan.
  2. "Basılı tut" gecikmesi → touch olaylarında 300-500 ms timer + browser
     scroll/gesture çekişmesi. Çözüm: pointerdown/pointerup ile
     touch-action: manipulation, passive:false, 250 ms eşik ve
     transform tabanlı görsel geri bildirim.
  3. Liste render'ı → çok DOM düğümü yeniden çiziliyor.
     content-visibility: auto + contain: layout paint, ve uzun listelerde
     sanal liste (virtual list).
  4. Animasyonlarda sadece transform/opacity kullan (top/left/width değil),
     will-change dikkatli kullan.
  5. Iframe katmanı bir miktar maliyet ekler; ileride temalar doğrudan React
     altında yüklenirse bu da kalkar.

Kütüphane önerisi (hafiften ağıra):
  - Motion One veya GSAP → 60 fps animasyon (Framer Motion'dan hafif)
  - virtua / @tanstack/virtual → uzun sohbet listesi
  - idb-keyval → hızlı IndexedDB
  - Hammer.js yerine Pointer Events API (yerleşik, en hızlısı)
  - Duvar kağıtları için sharp/squoosh ile WebP üretimi (build adımı)
Yani "yeni bir framework"e geçmek gerekmiyor; asıl kazanç görsel varlık
optimizasyonu + doğru event handling + precache.

B) BUBBLEWRAP / TWA / GERÇEK ARAMA EKRANI
  - Bubblewrap ile PWA'yı APK'ya çevirmek MÜMKÜN ve mantıklı.
  - Ancak saf TWA = Chrome kabuğu. Android'in GERÇEK sistem arama ekranı
    (tam ekran, kilit ekranı üzerinde, ConnectionService/Telecom entegre)
    saf TWA ile TETİKLENEMEZ.
  - Yapılabilecekler:
      * FCM data mesajı + high-priority notification ile tam ekran benzeri
        "Cevapla / Reddet" bildirimi (fullScreenIntent) → bu bir miktar
        native kod ister (TWA'ya küçük bir Android modülü eklenerek).
      * Gerçek telefon arama deneyimi için ConnectionService + Telecom API
        → native Android kodu şart (Kotlin/Java), Capacitor ya da özel
        TWA fork ile.
  - Pratik yol: Bubblewrap ile TWA üret, sonra projeye küçük bir native
    modül ekleyip fullScreenIntent + ConnectionService bağla. Web tarafı
    aynen kalır.
  - Alternatif: Capacitor'a geçmek (web kodu değişmez) ve hazır
    callkeep benzeri eklentileri kullanmak — en hızlı yol budur.

C) ARAYÜZLER PARA KAZANDIRIR MI?
  - Evet, mantıklı bir gelir modeli: tema/arayüz mağazası.
  - Çalışan örnek: Telegram (ücretsiz tema, Premium'da özel efektler),
    LINE (tema satışı ciddi gelir kalemi), WhatsApp'ta yok — burası boşluk.
  - Öneri: 3-4 ücretsiz tema + premium paketler (doğa, bisiklet, neon,
    futbol takımı). Futbol takımı temaları lisans gerektirebilir; taraftar
    renkleri/desenleri logosuz kullanılırsa risk azalır.
  - En iyi model: tek seferlik tema satışı yerine "Sohbeto Plus" aylık
    abonelik → tüm temalar + ekstra özellikler. Tekrarlayan gelir.
